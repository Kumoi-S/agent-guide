# 实验规划

三个应用任务分别观察任务表达、信息提供和工具执行如何影响交付。Prompt 和 Context 的结果提前准备，Harness 保留一次现场局部修改。具体办公材料、模型版本和绘图环境在试跑前确定。下文的案例是供选题和试跑的候选。

## 一、Prompt：任务表达实验

问题：面对同一项工作，不同的交代方式会带来哪些具体差异？两个模型在相同条件下的表现如何？

候选任务：把一份脱敏项目周报整理成给项目负责人的进度简报。材料包含进展、风险和待办，交付要求可检查事实、遗漏、顺序和格式。

### 对照设计

| 条件 | 给 Agent 的内容 |
| --- | --- |
| A 简单许愿 | 用一句话提出同一任务。 |
| B 结构化 Prompt | 明确目标、背景与依赖信息、要求与约束、交付形式和验收标准。 |
| C 简单任务描述 + Skill | 用简短指令提出任务，由 Skill 提供可复用的工作要求。 |

- 两个模型各跑 A、B、C，共六组。固定任务、原始材料、Harness、工具配置和验收清单，每组用独立会话，避免历史输出进入下一组。
- 如果要比较 Skill 的封装形式，逐项对齐 B 和 C 的工作要求、示例与参考资料，并记录 C 是否实际加载了 Skill。如果信息内容不同，按两套完整工作方案解释组间差异。
- 按同一清单评估完成情况、要求遵循、事实和格式质量、遗漏与意外表现。对人工修改成本，记录需要修的地方和实际用时，并保留有代表性的原文片段。

### 两个短对照

- 角色设定：选同一模型和一条 Prompt，只改角色描述，比较产物中具体的判断、措辞或取舍。
- 多轮修改：选一个已观察到的问题，用同一纠正要求分别改写原始 Prompt 后重跑，以及在原会话追加指令。记录修改是否生效、原有要求是否保留。结合结果讨论稳定要求如何回写，以及新情况如何在当前回合反馈。

现场素材：六组条件与结果总表、一两处代表性片段、短对照截图，以及可供下一段打开的实际 Skill 文件。

## 二、Context：信息提供小实验

问题：在同一任务中，额外提供哪些信息有帮助？如何看出 Agent 读过并使用了它？

候选任务：根据一份脱敏实施交接记录生成待办检查表。附加材料可用团队的交接字段规范，包含责任人、截止时间和待确认项的记录方式。原始材料中留一处信息缺失，观察产物怎样处理。

- 两组使用同一模型、Harness、任务指令、原始材料和工具配置，分别在独立会话运行。A 组仅提供原始材料。B 组在同样的材料之外提供一份与任务相关的规范、模板或参考资料。
- 记录 Agent 是否读取补充文件、引用了哪条要求，以及对应字段、结构、缺失信息处理或遗漏有何变化。用读取记录判断文件是否被访问，用交付物判断规则是否落实。
- 展示顺序：回看 Prompt 实验 → 打开 Skill → 一句话引出 Context → 用 Pi 查看实际 Context → 展示两组输入和输出 → 回到 Skills 的使用与管理。
- Context 是模型在当前步骤能够利用的信息集合，可能包含任务指令、历史对话、文件资料、项目规范、Skills、工具定义与返回结果、任务状态。Skill 是可发现、可选择、可按需加载的复用工作方法，可包含适用范围、触发条件、工作指令、参考资料、模板和脚本。

现场素材：原始材料及附加材料各一份、Pi 的相关记录、两组交付物的并列片段。

### Skills 配置备选对比

围绕基础 Read / Write / Edit / Bash、增加相关 Skills、增加较多 Skills / MCP 三种配置试跑同一任务。记录任务相关性、Skill 是否被发现和加载、工具是否实际调用、要求是否落实。分别增加 Skills 和 MCP 才能观察其各自影响。两者同时改变时，比较的是整套配置。可结合 SkillsBench 等公开研究讨论，引用时带上实际任务、模型与 Harness 条件。

## 三、Harness：结构化绘图与交付

问题：Agent 怎样选择和操作工具，把文字描述变成可检查、可编辑的交付物？收到局部修改要求后，能否改对并保留其余结构？

候选任务：用一段脱敏的需求评审或工单处理流程说明生成框图。保留一个有明确条件的分支，供后续修改节点和连线。

- 先准备一份人工核对的基准，列出应有的节点、方向、分支标签和终点。各工具方案使用同一份输入、交付要求和后续修改指令，尽量固定模型及 Harness。记录工具、绘图 Skill 和实际配置，便于解释组合效果。
- 以 Draw.io 为主要方案，和 Excalidraw、其他适用工具或绘图 Skills 做对照。检查节点完整性、连线方向、分支逻辑、布局可读性、局部修改的返工量，以及源文件是否可以继续编辑。
- 展示 Codex / DSH 的界面以及任务相关操作。从文字描述生成框图后，打开交付物核对结构，再现场做一次节点与连线的局部修改。改完重开源文件，检查目标改动、相关连线和周边结构。
- 用演示中的实际工作环境简要说明沙箱、权限与人工确认影响了哪项操作。讲工具优势时，指向这次任务和可核对的结果。

现场素材：各方案的并列图、可编辑源文件、基准清单、局部修改前后记录。提前留一份修改后的图，便于时间有限时直接展示对照。
