# Agent 使用：从入门到进阶

正式内容按 45 分钟安排，答疑另计。三个实验分别观察任务表达、材料提供和工具执行对交付的影响。

## 一、开头与 Harness 基本组件导览（5 分钟）

- **开场引入。** 提出贯穿整场的两问。「我会用网页 AI，Harness 能额外给我什么？」「把一件工作交给 Agent，我的哪些做法会影响它最后交回来的东西？」从第一问进入 Harness 导览，带着第二问看三个实验。
- **Harness 和网页 AI 的区别。** 从网页端已有 Agent 模式讲起，用 ChatGPT 的默认使用体验作例子。Harness 的区别在于使用者可以按工作需要自定义各个组件。
- **认识 Harness 的组件。** 先用示意图介绍 Harness 有哪些组件，再切到实际界面或用提前准备的画面，带大家认一下。

## 二、Prompt Engineering（12 分钟）

- **一件工作要交代清楚什么。** （待补充）Prompt 模板和示例。
- **两个模型 × 三种交代方式。** 同一任务分别用一句话许愿、结构化 Prompt、短指令加 Skill。先看输入具体差在哪，再看结果里哪些要求落实了、哪里出乎意料、哪些地方拿回来还得改。同一种交代方式也看两个模型的表现有没有差别。
- **关于角色设定的玄学。** 「实验等待结果时，穿插」只改角色描述，看结果里的判断、取舍或措辞怎么变。
- **结果不对，优先改原 Prompt。** 一开始就适用的要求漏写了或没说清楚，优先改原 Prompt 后重跑。任务中途出现新情况，或要在已有产物上做局部调整，就在当前会话里追加。用同一处问题对比两种改法，看问题是否修正、原有要求是否保留。
- **一句话衔接 Context。** 每次发消息都从头想怎么把 Prompt 写完整，很费时和精力。能不能把反复用到的要求和做法先整理好，下次交代任务时直接用上？由此引出 Skill，下一节再打开实验中用过的那份。

## 三、Context Engineering（12 分钟）

1. Skill 是 Prompt 的延伸（6 分钟）
- **Skill 怎么写。** 把 Prompt 里反复用到的做法写进 `SKILL.md`。用 `description` 写清适用场景，正文写 Agent 先做什么、什么时候要问人、最后交什么。以实施交接为例，先找出缺责任人或截止时间的事项，集中问一轮，再生成待办清单。暂时答不上来的标为「待确认」。
- **Reflect 小实验。** 展示一段修改交接清单的对话，里面既有对这次项目的事实纠正，也有以后每次交接都适用的要求。让 Agent 回顾对话，把可复用的做法写成 Skill。打开草稿看它提炼出了什么，再换一份交接记录，用同一个模型在两个新会话里发同一句短指令，其中一组显式调用 Skill。比较 Agent 会不会在出清单前主动询问缺失信息。

2. Skill 越多越好吗？（6 分钟）
- **多给内容也可能拖累结果。** SkillsBench 中，人工筛选的 Skill 平均提高通过率 16.2 个百分点，面面俱到的一组通过率下降 2.9 个百分点。另一项研究加入等长的无关 Skill 做对照，部分模型的通过率下降。先判断这次任务需要什么，再按需加载 Skill。[SkillsBench](https://arxiv.org/html/2602.12670v1#S4.SS2) · [无关 Skill 对照实验](https://arxiv.org/html/2608.23067v1#S4)
- **有些 Skill 适合由人点名。** 用 Pi 演示 `SKILL.md` 顶部的 `disable-model-invocation: true`。开启后，模型不会自动选用这份 Skill，用户仍可用 `/skill:名称` 主动调用。想让 Agent 进入「先问一轮、再出清单」的工作方式时，就点名调用交接 Skill。[Pi Skills 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md)
- **写 Skill 时，先想希望 Agent 怎么跟你配合。** 打开公开的 `grilling` Skill，看它怎么规定每轮问什么、什么时候等用户回答、拿到回答后怎么继续。分享一个实践判断：许多好用的 Skill 主要定义交互方式，知识起辅助作用。团队规范、模板和案例可以放在参考文件里，需要时再读。[grilling 的 `SKILL.md`](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)

## 四、Harness Engineering（6 分钟）

- **Codex 与 DSH 的工作方式。** 通过真实界面说明文件操作、文档或网页批注与修改、界面查看和工具执行。重点是能做什么、执行到哪一步在哪里看。
- **结构化绘图实验。** 用同一份流程描述对比 Draw.io、Excalidraw 等方案。比较结构正确性、布局、可编辑性和局部修改成本。保留一次现场局部修改，说明为什么要检查实际源文件。
- **执行控制。** 简要说明沙箱、允许操作的范围以及哪些操作需要人工确认。工具选择落在这次工作的交付要求上。

## 五、一些实用技巧（7 分钟）

- **多模型管理。** 用 Mapie 讲模型切换和按任务选模型。模型特点结合实际使用的版本。
- **信息安全与脱敏。** 内部材料在哪些获准环境使用，哪些信息要替换，哪些业务关系必须保留。
- **验收标准。** 提前约定怎么检查事实正确性、内容完整性、逻辑合理性和交付格式。
- **知识沉淀。** 把反复用到的业务规则、判断标准、模板和工作方法留下来。保留能说明适用条件的案例和失败经验。

## 六、总结（3 分钟）

回收三个实验。把事情说清楚，把信息给正确，让 Agent 真正执行，最后检查交付。落到一项手头已有、结果容易检查的工作。

实验案例、对照条件和评估维度见[实验规划](实验规划.md)。
