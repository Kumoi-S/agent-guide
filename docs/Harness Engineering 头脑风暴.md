# 四、Harness Engineering 头脑风暴

## 建议先试跑：在交接会上认领一项待办

第三部分结束时，大家手上已经有一份 Agent 整理过的交接清单。下一步就进入开会时会遇到的情形：会上有人接下了一项工作，主持人想当场填进清单，再继续确认下一项。把清单做成一个网页原型，现场用 Codex 的网页批注加上这一步。

这样能接回开场的两个问题。听众看到桌面工作环境怎么把已有文件、可操作的预览和页面反馈接起来，也能看到人怎么影响交付：**指给 Agent 看改哪里，说明改完要发生什么，最后自己试一次。**

### 试跑设计

- **初版。** 提前用第三部分的清单生成一页本地原型。展示事项、责任人、截止日期和状态。准备两项待确认，一项已有截止日期、只缺责任人，另一项已有责任人、仍缺截止日期。初版能看清单，会上认领的动作留给现场批注。
- **现场反馈。** 点在第一条的「待确认」上批注：「小周刚接了这项。让我在这里填责任人，确认后记进这条待办。它已有截止日期，填好后就移出待确认。」
- **验收。** 在改后的页面上填入小周。看这条的责任人是否更新、原截止日期是否保留，顶部待确认是否从 2 变成 1。再看另一条仍缺截止日期，是否继续留在待确认里。
- **试跑要核对的环节。** 确认批注能落到指定的行、修改后从哪里打开预览、当前权限下能否完成全程。留好初版和已改版本。现场若等待时间超出预演节奏，直接打开已改版完成验收。

原来的「点一下数字筛出两项」仍可作为轻量备选。首选认领是因为有一个明确的办公结果：会上确认的信息写回了清单，而且只有满足条件的事项才改变状态。

## 九分钟大纲提议

| 时间 | 讲什么、演什么 |
| --- | --- |
| 0–1 分钟 | **从清单到交接会。** 调出第三部分的清单和预制初版。指出那条只有截止日期的待办，交代为什么要在会上当场认领。 |
| 1–2 分钟 | **工具和工作环境。** 借开头认过的界面，快看一次 Codex / DSH 里怎么打开产物、从哪里给反馈。两边各带一个试跑确认过的实际操作，主实验留在 Codex。 |
| 2–6 分钟 | **给原型加上认领。** 打开 Codex 预览，点在对应事项上做批注并提交。等待时看一处和这次修改有关的执行记录，随后打开改后页面。 |
| 6–8 分钟 | **亲手走完一次认领。** 填小周，核对两条事项和顶部计数。让听众看到这条批注实际改变了什么。 |
| 8–9 分钟 | **借刚才的文件操作讲沙箱。** 说明演示时 Agent 能访问哪个工作目录、什么操作需要人工确认。用刚才验收的几步接到后面的实用技巧。 |

## 四个模型的独立构思

通过项目外的 Magpie 模型列表脚本确认模型后，分别启动了四个独立子代理。以下是它们的提案摘要。案例、时间分配和对照均待试跑。

### gpt-6.2-astra

- **交接会上认领。** 选只缺责任人的一项，把批注点在那一行。填好后核对待确认数量、原截止日期和另一条待确认项。把台上对照放在同一个动作的修改前后。
- **活动预算试算。** 在预计总额旁批注，场租固定为 3,000 元，餐费按每人 80 元计。把人数从 30 改到 40，核对总额从 5,400 元变为 6,200 元，再改回去复核。适合独立开场，验证特别快。

### glm-5.3

- **待办确认页。** 初版具备筛选和复位。把批注点在「待确认」的说明旁，要求展示具体的确认人和时间，比如「小周周五前确认」。运行后核对筛选、复位和显示出来的责任信息。这一版最轻，但现场修改以信息表达为主。
- **客户问题分类页。** 从客户反馈中找出需要人工跟进的一条，批注标明 24 小时内回复并置顶。验收分组、汇总统计和原始记录是否仍可核对。业务感强，需要先解释跟进规则和材料来源。

### deepseek-v4.1-flash

- **按原因拆分待确认。** 在顶部筛选区批注，把一个笼统的「待确认」拆成「待补资料」和「待定负责人」。分别点开两类看对应记录、计数和空状态，再恢复全部。适合讲一处反馈怎样同时影响分类和交互。
- **决策与假设追踪。** 在「预计提升 20%」旁批注，这是待验证的假设。请 Agent 统一标记多处引用，并整理依据、责任人和验证日期。验收每处标记和回链。这个方案适合讲改动如何传到一份产物里的其他地方，准备和核对都更重。

### gpt-5.6-sol

- **补齐字段后转为可执行。** 从事项卡打开补充面板，填责任人和截止日期。核对状态迁移、两个分类的计数和复位。这一版更完整，可以在「现场认领」之外扩展，首次演示只需保留最有代表性的一个字段。
- **会议决策核对页。** 决策缺负责人或原始依据时标记为未闭环。补齐后核对状态和汇总。重点是决策能否追溯，可以用来替换交接案例。

## 要不要再加一组对照

**台上先用同一笔认领的修改前后。** 观众看一遍就知道卡在哪、改完能做什么。前两节已经有 Prompt 和 Skill 对照，这里把时间留给页面上的协作和验收。

**如果要单独观察批注带来的差别，可以在试跑时做。** 同一个模型、同一个初版、同一条业务要求，分别从聊天里说明位置和直接在页面上批注。比较反馈者需要交代多少定位信息、Agent 有没有改到正确那行。仅当差别足够具体时，现场放一个并排片段。

模型也提出了「文字建议与就地修改」的对照。可以用来解释交付形式，用它比较产品需要实际控制工具、材料和权限。开场已经提到网页 AI 也有 Agent 模式，第四部分可以直接展示这次工作在哪个环境里怎样做成。
